# SPA-приложение "Custom Clothes" — Лабораторная работа №6

Это одностраничное приложение (SPA) для демонстрации каталога кастомной одежды, переработанное для работы с бэкендом на Node.js с использованием фреймворка **Express**.

Проект объединяет фронтенд (React с Redux Toolkit и i18next) и бэкенд (Express.js), демонстрируя полный цикл взаимодействия клиент-сервер.

## Основные технологии

*   **Фронтенд:**
    *   React (функциональные компоненты, хуки)
    *   Redux Toolkit (управление состоянием)
    *   React Router (навигация)
    *   React Bootstrap (компоненты UI)
    *   i18next (интернационализация)
*   **Бэкенд:**
    *   Node.js
    *   Express.js (фреймворк для веб-сервера)
    *   `fs.promises` (для работы с файловой системой)
    *   `cors`, `body-parser`, `xml-js` (вспомогательные библиотеки)

---

## Структура проекта

*   `server.js`: Основной файл бэкенда на Express.js, который обрабатывает все API-запросы и отдает фронтенд.
*   `data/products.json`: JSON-файл, в котором хранятся все данные о товарах. Сервер читает и записывает в него.
*   `src/`: Папка с исходным кодом фронтенд-приложения React.
    *   `src/app/store.js`: Конфигурация Redux Store.
    *   `src/features/products/productsSlice.js`: Redux-слайс для управления данными о товарах и взаимодействия с API.
    *   `src/features/ui/uiSlice.js`: Redux-слайс для управления состоянием UI (модальные окна).
    *   `src/components/`: Переиспользуемые React-компоненты.
    *   `src/pages/`: Компоненты страниц React (CatalogPage, HomePage, AboutPage).
    *   `src/i18n.js`: Конфигурация интернационализации.
*   `public/locales/`: Папки с JSON-файлами переводов для i18next.
*   `build/`: Папка с собранным фронтенд-кодом React (генерируется командой `npm run build`).

## Реализация API-сервисов (Backend)

Все API-сервисы реализованы в файле `server.js`.

1.  **`GET /`**
    *   **Тип:** Возвращает веб-страницу с фронтенд-кодом.
    *   **Описание:** Отдаёт собранный `index.html` (React-приложение).
    *   **Метод:** `app.get('/')`

2.  **`GET /api/products`**
    *   **Тип:** Возвращает данные в формате JSON.
    *   **Описание:** Возвращает полный список всех товаров из `data/products.json`.
    *   **Метод:** `app.get('/api/products')`

3.  **`POST /api/products`**
    *   **Тип:** Принимает данные и возвращает данные в формате JSON.
    *   **Описание:** Принимает JSON-объект нового товара, добавляет его в `data/products.json` и возвращает обновлённый список товаров.
    *   **Метод:** `app.post('/api/products')`

4.  **`PUT /api/products/:id`**
    *   **Тип:** Принимает данные (по ID) и возвращает данные в формате JSON.
    *   **Описание:** Принимает ID товара в URL-параметрах и JSON-объект обновлённых данных в теле запроса, обновляет существующий товар в `data/products.json` и возвращает обновлённый объект товара.
    *   **Метод:** `app.put('/api/products/:id')`

5.  **`DELETE /api/products/:id`**
    *   **Тип:** Удаляет данные.
    *   **Описание:** Принимает ID товара в URL-параметрах и удаляет соответствующий товар из `data/products.json`. Возвращает сообщение об успехе.
    *   **Метод:** `app.delete('/api/products/:id')`

6.  **`GET /api/products/export`**
    *   **Тип:** Возвращает данные в формате XML/HTML/JSON в зависимости от заголовка `Accept`.
    *   **Описание:** Отдаёт список всех товаров в запрошенном формате (`application/json`, `application/xml`, `text/html`).
    *   **Метод:** `app.get('/api/products/export')`

### Обработка исключительных ситуаций на бэкенде:

*   `app.post('/api/products')`: Проверяет наличие `name` и `price`.
*   `app.delete('/api/products/:id')`: Возвращает 404, если товар не найден.
*   `app.put('/api/products/:id')`: Возвращает 404, если товар не найден.
*   `readProducts()`: Обрабатывает случай отсутствия `products.json`.
*   Все сервисы имеют `try-catch` блоки для обработки общих ошибок сервера (500 Internal Server Error).

### При изменении JSON-файлов приложение продолжает работу:
*   Бэкенд читает `data/products.json` при каждом соответствующем запросе. Это гарантирует, что любые внешние изменения в файле будут отражены при следующем запросе.

## Реализация на фронтенде (React)

1.  **Получение данных с бэкенда:**
    *   Все операции с данными (получение, создание, обновление, удаление) теперь выполняются через **асинхронные thunk-экшены Redux** (`fetchProducts`, `addNewProduct`, `updateProduct`, `deleteProductById`) в `src/features/products/productsSlice.js`.
    *   Эти thunk-и отправляют `fetch`-запросы на соответствующие API-эндпоинты бэкенда (`http://localhost:5000/api/products`).

2.  **Отображение данных:**
    *   Список товаров отображается в виде карточек (`ProductCard.js`) на `CatalogPage.js`.
    *   Формы для создания/редактирования выводятся в модальных окнах (`ProductForm.js`).

3.  **Обновление данных:**
    *   При добавлении, редактировании или удалении товара, соответствующий Redux-экшен (`addNewProduct`, `updateProduct`, `deleteProductById`) отправляется на бэкенд.
    *   После успешного ответа от сервера, Redux `store` обновляется (либо перезагрузкой данных, либо изменением массива `items` напрямую), что автоматически вызывает перерисовку компонентов React (`CatalogPage.js`).

4.  **Скачивание файлов:**
    *   На `CatalogPage.js` добавлены кнопки "Скачать JSON", "Скачать XML", "Скачать HTML".
    *   По клику на них вызывается функция `downloadFile`, которая отправляет GET-запрос на `GET /api/products/export` с соответствующим заголовком `Accept` и инициирует скачивание файла.
